# GymFinder Mobile

React Native / Expo SDK 58。Web版は開発対象外です。

## 起動

Node.js 22.13以上（検証: 24.19.0）を使用します。

```sh
cd mobile
npm ci
npm start
```

iPhoneにSDK 58対応のExpo Goをインストールし、開発PCと同一LANでMetroのQRを読み取ってください。クラウドのlocalhostはiPhoneから接続できません。クラウドからの実機接続には、別途到達可能なネットワーク経路が必要です。この環境ではiPhone実機・シミュレーターによる表示確認を行っていません。

クラウドでホームディレクトリが書込不可の場合は `npm_config_cache=/tmp/gymfinder-npm` と `EXPO_NO_TELEMETRY=1` を指定します。Expoの設定保存先も書込不可の場合は、シェルから `__UNSAFE_EXPO_HOME_DIRECTORY=/tmp/gymfinder-expo`、`XDG_CACHE_HOME=/tmp/gymfinder-cache` を指定します（認証情報を持たない開発用キャッシュとして使用）。Expo APIがネットワーク制限を受ける場合、`EXPO_OFFLINE=1` でSDK同梱の互換情報を使用できます（APIの最新互換検証は行われません）。

## 構成

- `App.tsx`: 型付きReact Navigationの5タブ、Safe Area Provider、ダークテーマ
- `src/components/ui.tsx`: 共通の画面・カード・入力・ボタン
- `src/screens/`: Gyms / Training / Home / Diet / My Page
- `src/data/equipment.ts`: 既存器具ガイド3種目のデータ
- `src/state.tsx`: 端末内保存、記録・お気に入り・自宅器具の共有状態

記録・お気に入り・自宅器具はAsyncStorageで端末内に保存し、再起動時に復元します。Gymsの店舗情報・設備は検証用データです。Dietのグラフ/PFCは入力したログから表示します。Gymsのマッチ率は選択条件から計算します。全12種目の図解は実装済みです。設備投稿はこの端末内で利用できます。位置情報・実AI写真推定・公開投稿/API連携は今後のタスクです。写真は操作時にシステムの写真選択で指定し、位置情報は取得しません。カスタムフォントは未同梱でシステムフォントを使用します。

## TASK-007: 検索・マッチ率

`src/data/finder.json` は `index.html` の `DATA.proMenus`（16種目）、`proMuscles`（10部位）、`equipments`、`gyms`（5店舗）から必要なフィールドだけを移植したJSONです。店舗設備・メーカー・重量の真偽は未検証です。Webファイルを実行時に参照せず、APIへの通信や位置情報取得も行いません。

`src/domain/matching.ts` の純粋関数は `index.html` の `calcMatch` 本格モードを基準に、選択種目65% + 部位の器具保有率20% + ダンベル重量15%を四捨五入します。同じ器具を使う複数種目もそれぞれカウントします。種目を選んで全条件一致なら99%、最低15%という元の仕様を保持します。例: 8種目中7種目が対応、部位指定なし、重量充足なら `round((7/8 × .65 + .20 + .15) × 100) = 92%`。

移植時の改善: 全条件未選択ならスコアなし。重量不足ならダンベル種目も実行不可。不足器具は重複を除去。初心者モードや `app.js` の距離加点ロジックは今回の対象外です。

UIの重量指定は片手あたり0（指定なし）/20/40/60/90kg以上の必須フィルターです。検索語・地域とAND条件で絞り込み、マッチ率順に並べます。該当なしでも条件外の店舗を代替表示しません。「検索をクリア」は検索語・地域・重量のみをリセットして種目/部位選択を保持します。Gymsの検索条件・種目選択は起動中のみです。お気に入りは端末内に保存します。

テスト9件: 既存ナビゲーション2件、検索/種目選択の画面操作2件、計算・重複・重量境界・絞り込み・ランキングの単体テスト5件。

## TASK-009: 家トレ管理

- `src/screens/HomeScreen.tsx`: 自宅器具プロファイル、部位別/ジム種目別の提案、選択種目の記録。
- `src/domain/homeTraining.ts`: 6部位・18種目のカタログと純粋な提案/代替/入力検証ロジック。ダンベル/ベンチ/懸垂バー/バンドの全必要条件を満たす種目のみ表示。自重のみモードは器具登録を消さず器具種目を除外。
- ダンベル最大重量は片手あたり0より大きく100kg以下。入力後「最大重量を保存」で反映。記録重量はその上限まで、回数・セットは1〜100の整数。自重・バンドは回数とセットのみで記録し、以前入力した重量を使いません。
- 代替検索はチェストプレス/ラットプルダウン/レッグプレス/シーテッドロー/ショルダープレス/ケーブルカール/アブドミナルクランチの7種。代替がない場合は候補なしを表示。広背筋のマシン動作と自重Wレイズなどは完全な置き換えではなく、画面のフォーム説明に限界を記載。
- `src/domain/fitnessStorage.ts` / `src/state.tsx`: バージョン付きデータをAsyncStorageに保存。履歴にlocation/loadTypeを持ち、My Pageで「🏠 自宅」、自重/バンド/片手kgを区別。既存Training記録は「ジム」に分類。
- プロファイル・統合履歴・お気に入りは端末内保存。クラウド同期はありません。保存中/保存済み/エラーを表示し、書込み失敗は再試行可能。読込みエラーや未知の形式では既存データを初期値で上書きせず、読込み再試行を表示。

実機レビューでは、器具なし→ダンベル→ベンチ追加、自重のみ切替、6部位の候補、代替の候補なし、片手上限を超える入力、My Pageの自宅タグ、アプリ再起動後の復元を確認してください。


## TASK-010: 食事・体重管理

`DietScreen.tsx`、`WeightChart.tsx`、`domain/nutrition.ts` を追加。サンプル数値ではなく入力した体重・食事を使います。記録日は端末のローカル日付を使い、今日以前を選択できます。日付の入力後は「日付を表示」で確定した日が表示・保存先になります。同日の体重は更新し、グラフは直近30記録を日付の間隔に従って配置。体重・目標は20〜400kg（目標は空欄で未設定）、日目標100〜10000kcal、食事のP/F/Cは各0〜1000gです。

PFC比率はP/Cを4kcal/g、Fを9kcal/gで換算します。食品の入力kcalは独立して集計するので、PFC換算熱量と一致しない場合があります。空欄・負数・NaN・不正日付を拒否し、カロリー超過を表示します。食事は朝昼夕間食から選び、確認ダイアログで削除できます。

写真ライブラリから選択した画像には実AI解析を行わず、必ず580kcal/P52g/F16g/C55gのモック値を提示します。写真の選択だけではログ追加せず、入力欄で確認・修正して「食事を保存」で記録。画像とURIは端末ストレージやサーバーに保存せず、一時的な画面表示にだけ使用します。キャンセル/失敗は現在の入力を保持します。

保存キー `@gymfinder/fitness/v1` は既存データを見つけるため維持し、内容のschema versionを2へ更新。v1は旧記録・器具プロファイル・お気に入りを保持し、空の食事/体重ログと目標設定を追加して移行します。v2の新ログも保存・復元します。未知バージョンや壊れたデータは初期値で上書きせず、読み込み再試行を表示します。

検証: 全37テスト（写真ライブラリはモック）。実機の写真ライブラリとネイティブビルドは未検証です。`npm run typecheck`、`npm test -- --watch=false` とiOS/AndroidのExpo exportが成功しています。


## TASK-011: ジムへの投稿

Gymsの各カードの「投稿する」、またはMy Pageの「あなたの投稿」からジムを選び、設備修正・設備写真・レビューを登録できます。

- **設備修正**: 最大ダンベル重量0〜200kg（空欄なら変更なし）と未設置器具の追加申請、任意のメモ。修正履歴を元カタログに重ね、検索・重量フィルター・適合スコアへ反映します。同じ重量だけ・器具重複・不正な入力は拒否。0kgにするとダンベル器具を除外します。
- **設備写真**: ライブラリ選択、またはカメラ許可後に撮影。説明1〜120文字、任意の器具を関連付けて明示的に投稿。画像は20MB以下、`expo-file-system/legacy` のdocument領域 `gym-photos` にコピーします。保存メタデータは相対ファイル名で、一時キャッシュURIや画像base64をAsyncStorageへ入れません。写真を読めない場合は代替表示。
- **レビュー**: 星1〜5と1〜1000文字のコメント。表示する平均はこの端末の投稿分だけです。

投稿は**端末内のみ・未検証**です。外部サーバーへの送信、他ユーザーへの公開、店舗/運営への申請送信は行いません。元のプロトタイプデータを公式情報として確定する機能でもありません。端末保存の失敗は既存の再試行UIで扱います。

保存内容をschema v3へ拡張し、v1/v2から運動・家トレ・食事・体重・お気に入りを保持して移行します。元の保存キーを維持します。写真はアプリ専用領域にあり、アプリ削除で失われます。公開共有・写真削除/通報・承認ワークフロー・クラウドバックアップは別途設計が必要です。

検証は全52テスト（15件追加）と型チェック・両OSバンドル。写真/ファイルAPIはテストではモックです。iPhoneの実カメラ・権限・コピー・再起動復元はExpo Goで別途実機レビューしてください。

企画の背景・将来構想・レビュー論点は `../docs/GYMFINDER_PROPOSAL.md` を参照してください。

## TASK-013: 日英の動的切替

共通ヘッダーの「🇯🇵 日本語 / 🇺🇸 English」で言語を変更できます。FitnessProviderのlanguage/setLanguageと `src/i18n` の辞書・LocaleProviderを使い、5画面とタブラベル、入力の説明・エラー、12種目と家トレのガイドを切り替えます。TASK-016では、ブランド見出し・既知のブランド/店舗名・単位も選択言語へ切り替えます。利用者が入力した食事名・投稿の原文は保持します。元からあるシステムの種目名だけを表示時に翻訳し、記録値を書き換えません。

言語はAsyncStorageの既存データへ保存（schema v4、保存キーは維持）。v1/v2/v3は日本語へ移行し他の記録は保持します。不明な言語値はjaへ補正。保存失敗の表示・再試行は選択言語で表示します。言語変更だけで画面遷移やフォーム初期化を行いません。

翻訳キーは日本語の原文、値のある文は `{0}` 等の明示的な補間です。ユーザー文字列を自動翻訳しません。辞書にない新しい文は原文にフォールバックします。今後の文言追加時は日本語・英語の両辞書とカタログテストも更新してください。日付の表示にja-JP/en-USを使い、日付入力のYYYY-MM-DDや数値の保存形式は維持します。外部APIとブラウザーLocalStorageは不要です。

検証は全61テスト（既存52件+言語9件）、型チェック、release:check、両OSバンドル。実機での長文折返し・文字拡大・読み上げ・言語復元はレビュー待ちです。


## TASK-016: 完全言語分離

システムが提供する文言・全5画面・12種目の図解/ガイド・器具/ジム情報を言語ごとに表示します。`src/i18n/ja.json` / `en.json` が表示辞書、`messages.ts` がReactに依存しない補間・単位表記、`index.tsx` が言語状態との接続です。日本語では既知ブランドをカタカナ表記にし、キログラム/グラム/キロカロリーなどの単位も日本語化。英語では日本語の補足を表示しません。日付・数値の保存形式、種目ID、元カタログ、既存の記録を変更せず、表示で変換します。

利用者のレビュー・確認メモ・食事名などは自動翻訳しません。未知の利用者入力を正規表現で削ったり、保存済みの原文を書き換えたりしません。英語モードの画面に利用者自身の日本語入力が含まれることは許容範囲です。カタログの日本語名・英語名のどちらでも検索でき、切替後も同じ検索条件を保ちます。

Webの`../index.html`も独立した日本語/英語の表示辞書を持ち、データ・テンプレートから選択言語を組み立てます。DOM全体の後置換は行いません。利用者投稿は原文を文字列として表示し、検索欄のDOMを保持して結果領域のみ更新します。

```sh
npm ci
pnpm test --watch=false
pnpm exec tsc --noEmit
pnpm test:web
npm run release:check
```

依存関係は引き続きpackage-lock.jsonを使用します。`pnpm-workspace.yaml`は単一パッケージの実行設定としてpnpm 11のスクリプト実行前の自動再インストールを抑え、npm ciで導入した依存関係を使用します。Web検証用jsdomは開発依存として明示しています。既存61件と今回追加の言語分離7件（全13 suites/68件）を対象にします。TASK-014側から報告された別の7件は、このリポジトリへ未共有です。

`pureLanguage.test.tsx`は画面/説明/プレースホルダー/読み上げラベル、全ガイド、既知ブランド・単位、辞書の補間、原文保持、検索を検証します。`scripts/verify-web-language.cjs`はWebの両モード・全タブ・詳細条件・投稿などの言語混入と実行エラー、検索フォーカス・原文保持を検証します。iPhoneの実表示・読み上げ・キーボードと署名済みアプリへの反映は別途確認が必要です。
