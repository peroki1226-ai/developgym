# GymFinder ネイティブアプリ開発方針

更新日: 2026-11-02（日本時間）。ユーザーの「これからアプリ化していきたいから、それをもとに進めたい」という指示を反映する。現在のタスク状態は[DEV_STATE.md](../DEV_STATE.md)を正とする。

## 開発の本体

- `mobile/` の React Native / Expo アプリを継続開発する。既存の5タブ・記録保存・日英切替を土台にする。
- iPhoneを主な実機検証端末とし、Androidにも同じコードベースで対応する。
- ユーザーが採用した白青の参考画像を画面基準にする。[画面刷新仕様](TRAVEL_REDESIGN.md)に従い、日本語/英語の表示分離、ブランド・単位の日本語化を維持する。
- 利用者が入力した記録やレビューの原文・保存データを、表示変更だけで書き換えない。
- Web/PWAは補助的なプレビューとして保持する。通常の機能追加・改善は`mobile/`へ実装し、Pages公開や一時トンネルの復旧はアプリ開発の前提にしない。

## 進める順番

| 順番 | 目的 | 完了の確認方法 |
|---|---|---|
| 1 | 配布済みアプリとソースを揃える | 実機に入っているアプリのEAS Build ID・ソースコミット・Bundle IDを照合し、未同期のTASK-014/015差分と配布設定を統合する |
| 2 | 最新版をiPhoneへ届ける | 既存のExpo/EASプロジェクト・Appleチーム・署名を確認し、更新用ビルド番号を確定。TestFlightを通常の進捗確認経路として初回インストール・次回の上書き更新を確認する |
| 3 | 実機で使いやすくする | 5タブ、検索と日本語入力、図解、家トレ/食事の記録、写真、日英切替、再起動復元、Safe Area・文字拡大をiPhoneで確認し修正する |
| 4 | ストア公開へ進む | 受入済みビルド、スクリーンショット、説明文、プライバシー関連情報を揃え、App Storeへ申請。Androidでも実機確認してGoogle Play向けに進める |

各段階で、実装・自動検証・署名付きビルド・実機インストール・ストア公開の状態を分けて記録する。新機能はこの計画と整合させてタスク化する。

## 更新時の基準

機能を変更したら関係するテストと型チェックを行い、配布前にはリリース設定とiOS/Androidバンドルを確認する。署名付きビルドでの実機検証後、ソースコミットとビルドIDを記録してレビューへ渡す。ビルド番号はEAS remoteで自動増分し、初回は配布済み最大番号と照合する。既に使ったビルド番号を再利用しない。

食事写真は現状モック推定、投稿は端末内保存である。実AIや複数利用者への公開共有は別途要件化し、実装前に対応済みと表示しない。ブラウザー・Expo Go・署名付きアプリ間での記録の自動移行も前提にしない。

## 進捗確認用の配布基準（TASK-018）

ユーザーが確認する配布物は、アプリ本体にコードを内蔵した署名付きReleaseビルドとする。Expo Go/開発クライアントや一時Webトンネルへの接続を、通常の進捗確認の前提にしない。確認用previewとproductionの両方をdevelopmentClient=falseにし、起動時OTA取得を無効化する。最新版はビルド番号を更新したアプリとして配布する。

受入時にはMetro/トンネル停止・iPhone機内モードで完全終了後の起動、5タブ操作、記録保存・再起動復元を行い、EAS Build IDとソースコミットを記録する。

## インストール・更新の運用

通常の配布はTestFlightに統一し、[iPhone導入ガイド](IPHONE_INSTALL.md)を使用する。初回は招待からインストール、次回以降は更新する。配布担当が提出処理・テスター割当・有効期限・実機での更新とデータ保持を確認した後、最新版のビルド番号・短い変更点・有効な招待1件を案内する。Ad Hocは登録端末向けの補助経路とする。
