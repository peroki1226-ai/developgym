# iPhoneでGymFinderを確認する

今後の通常の進捗確認はTestFlightに統一します。最新版は同じアプリを更新して確認します。

**現在の状態：iOS 1.0.0 (3)がEASでビルド進行中との報告。TestFlight提出・配布は未確認で、招待リンクは未発行です。**

対象ビルドID：`9ba7dd8b-a1e4-4c34-a2cb-4ee5b225c785`。受領時点の状態で、ライブ更新ではありません。

## 最初の1回

1. App StoreからAppleの「TestFlight」を入れる。
2. 配布担当から届いたGymFinderの招待を開き、参加する。
3. TestFlightでGymFinderの「インストール」を押す。

招待・インストールにはインターネット接続が必要です。招待を受けたApple Accountで進めます。

## 次回から

TestFlightでGymFinderの「更新」を押します。自動更新が利用できる場合は有効にできます。変更内容・実際のビルド番号を添えて案内するので、更新した版を確認できます。

記録を残すため、通常の更新ではアプリを削除しません。新しい版が表示されない場合は、配布担当が処理・テスターグループへの割当・有効期限を確認します。

起動に開発PC、同じWi-Fi、Expo GoのQR、一時トンネルは必要ありません。外部地図等のオンライン機能には接続が必要です。

Safariの「ホーム画面に追加」で作ったWeb版は保存領域が異なります。Web版の記録が自動で移るとは扱わず、移行確認前にWeb版の消去を案内しません。

## 配布担当の準備と受入

ユーザーへ渡す通常の入口は、実際に利用できるTestFlight招待1件に揃えます。未発行のURL・期限切れの招待・一時Web URLは配布リンクとして案内しません。

- 既存のExpo/EASプロジェクト、Appleチーム、App Store ConnectのGymFinderアプリを照合する。配布済みアプリと同じ識別子・署名を継続使用する。
- `mobile/`で`npm run build:ios:production`を実行する。設定・型・テストの検証後にEASの署名ビルドへ進む。ビルド完了はTestFlight配布完了とは別。
- 検証済みのEAS Build IDを指定してApp Store Connectへ提出する。`--latest`で別のビルドを選ぶことを避け、提出先アプリも照合する。
- Apple側の処理完了、必要な申告、テスターグループへの割当、対象者の参加、ビルド有効期限を確認する。外部テスターではBeta App Reviewが必要になる場合がある。TestFlightのビルドは最大90日で失効するため、期限前に更新を用意する。
- 初回はiPhoneへのインストール、PC/Metro/トンネル停止・機内モードでの完全終了後の起動、5タブ、保存、再起動復元を確認する。
- 次回は同じアプリへの上書き更新を試し、更新前の記録を保持することと、案内したビルド番号になっていることを確認する。

署名・提出の詳細は[リリース手順](../mobile/store/RELEASE.md)を参照。認証済み環境で必要な連携を行い、トークンやAppleのパスワードを文書へ記載しません。

## 配布できる時点で案内する内容

- **最新版**：バージョンと実際のビルド番号
- **変更点**：今回確認してほしい変更を短く記載
- **操作**：初回「インストール」／次回以降「更新」
- **入口**：有効性を確認したTestFlight招待

開発記録にはソースコミット・EAS Build ID・提出/配布の結果・実機確認結果を別途残します。招待の有効性とインストールを確認するまで、「配布済み」「すぐ使える」とは記載しません。
