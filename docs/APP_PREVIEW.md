# アプリの模型をAntigravityで確認する

## 今回の原因

利用者が見ていたのはAntigravityのプレビュー。`gym-app-preview.html`は旧`index.html`へ転送していた。一方、三次元模型・筋肉・低速再生の実装先は`mobile/src/`。旧WebにはReact Nativeのコードを読み込む経路がなく、モバイルのテストやバンドルが成功しても、そのプレビューの見た目は変わらなかった。

このチェックアウトで転送とコード分離を確認した。Antigravity側の実際の起動コマンド・現在の配信内容はこの環境からは検査できていない。**ソースの修正・pushと、別環境での表示反映は別々に確認する。**

## Antigravityでの起動

リポジトリを同期した後、既存の3000番ポートのプレビューサーバーを停止し、次を実行する。

```sh
cd mobile
npm run preview:app
```

表示された`http://localhost:3000/app-preview/`をAntigravityのブラウザープレビューで開く。既存サーバーを残す場合は`npm run preview:app -- --port 3001`とし、3001番の表示へ切り替える。`localhost`は起動したPCを指すので、このアドレスをiPhone向けの公開リンクとして案内しない。

このサーバーでは`/`と`/index.html`も同じアプリ版へ移動する。`/gym-app-preview.html`は生成元を確認してからアプリ版へ移動する。古いWebへは戻さない。アプリ版が未生成の場合は起動手順を表示する。

ビルドだけの場合は`npm run preview:app:build`。生成物はGit管理外の`app-preview/`。本体と同じ`mobile/App.tsx`・画面・データ・三次元描画をExpo Webとして生成する。模型をWeb用に再実装したり、別HTMLの図を同期したりしない。

## 表示確認

1. `/app-preview/preview-info.json`の`source`が`mobile/App.tsx`、`kind`が`expo-app-preview`であることを確認する。`sourceHash`は作業ツリーのアプリソースを含む指紋、`commit`は生成時点のHEADであり未コミット差分の有無を表すものではない。
2. 探索画面から「マシンの使い方」ガイドを開く。三次元模型、筋肉の形、対象筋の着色が表示されることを確認する。
3. 前・横・後ろの視点、構える/動かす/戻す、低速再生と停止を操作する。
4. 比較する画面のスクリーンショットと`preview-info.json`を一緒に記録する。見た目について利用者の受入を確認するまでTASK-031を完了にしない。

サーバーはHTMLと生成元情報をキャッシュしない。アプリソース変更後は古い生成物の表示を409で止め、再実行を案内する。保存データは消去しない。以前のWeb版とアプリ版の保存キーは異なり、記録が自動移行されるとは扱わない。

## この修正の範囲

- 直したのは**アプリの実装をプレビューへ届ける経路**。人体/器具の造形を今回改良したわけではない。
- 現模型は手続き生成した模式模型。実物のハンマーストレングスを照合したモデルや、医学監修済みの筋骨格モデルにはなっていない。TASK-029の実機器具照合とTASK-031の見た目の受入は継続する。
- Expo Webの実描画確認はiPhoneネイティブの確認ではない。Antigravity側での起動、iPhone更新、署名ビルド、配布は別途。TestFlightは保留のまま。今回EASジョブは実行しない。
- `preview:build`/`preview:check`と既存Pagesワークフローは旧Web/PWAの公開準備用。**模型の最新状態の確認には使わない。**旧Webの機能・公開設定は変更しない。
