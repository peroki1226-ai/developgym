# GymFinder プロダクト企画書

**Antigravity レビュー用｜2026年10月27日｜企画案 v1**

> やりたいトレーニングから、通うジムを選ぶ。
> 器具がなければ、家でできる代替メニューまで見つかる。

## 1. 企画の結論

GymFinderは、**希望する種目とジムの設備を照合し、自分に合うトレーニング場所を探せるiOS / Androidアプリ**です。

「近いジム」「安いジム」に加えて、「今日やりたい種目ができるか」「必要な重量があるか」を判断材料にします。長期的にはジム・家トレ・食事を横断する総合フィットネスアプリを目指しますが、初期の訴求は **『自分のメニューができるジムを探す』** に集中します。

これは競合との差別化に関する仮説です。市場優位性や需要を実証済みと扱わず、実店舗・利用者で検証します。

## 2. 誰の、どんな困りごとを解決するか

| 利用者 | 困りごと | GymFinderが提供する判断材料 |
|---|---|---|
| 初心者 | どの器具を使えばよいか分からない | 部位・器具の説明、フォーム図解、初心者向け手順 |
| 本格トレーニー | ダンベル上限や目的のマシンが来店前に分からない | 最大重量、器具一覧、希望メニューとの対応表 |
| 出張・旅行者 | 初めての土地でも普段のメニューを続けたい | 地域・重量・種目を組み合わせた検索 |
| 家トレ利用者 | ジムの種目を手持ち器具でどう代替するか迷う | 所有器具に応じた部位別メニュー・代替候補 |
| 継続したい利用者 | 運動と食事の記録が別々で振り返りにくい | 運動履歴と食事・体重管理を同じアプリに集約 |

## 3. 最初に検証する体験

```text
やりたい種目・重量を選ぶ
          ↓
設備が合うジムを比較する
          ↓
できる種目・不足器具を確認する
          ↓
実店舗でトレーニングする
          ↓
記録する・設備情報を更新する
```

ジムに行けない日は、家トレ画面で所有器具を選び、同じ部位を鍛える候補を探します。

成功の基準は画面の完成だけではありません。**来店時の設備情報が検索結果と合い、希望のトレーニングができたか**まで確認します。

## 4. 5つの画面と役割

| タブ | 役割 | 主な機能 |
|---|---|---|
| Gyms | 今日のトレーニング場所を選ぶ | 地域・種目・器具・重量検索、適合スコア、対応／不足一覧 |
| Training | ジムで正しく動き、記録する | 12種目のフォーム図解、初心者／本格モード、セット記録 |
| Home | 手持ち器具で運動を続ける | 器具プロファイル、6部位の提案、代替逆引き、自宅記録 |
| Diet | 食事と体重を振り返る | 目標設定、体重グラフ、日別食事、カロリー・PFC |
| My Page | 自分の積み重ねと投稿を確認する | ジム／自宅の統合履歴、お気に入り、自分の投稿 |

家トレ・食事は既存実装を活かします。ただし初回案内で全機能を説明せず、まずジム検索の価値を短く伝える方針を提案します。

## 5. ジムの適合スコア

現在の実装は、以下の重み付き計算です。

| 要素 | 重み |
|---|---:|
| 選択した種目の対応率 | 65% |
| 対象部位に必要な器具の保有率 | 20% |
| 必要ダンベル重量の充足 | 15% |

四捨五入して表示します。未選択の項目は充足扱い、全条件未選択ならスコアなし。選択種目の全条件一致は99%、下限は15%というプロトタイプの仕様を引き継いでいます。

**重要な区別：92% MATCHは『選択種目の92%ができる』ことを直接意味しません。** 例えば8種目中7種目が対応し、部位指定なし・重量充足なら総合スコアは92%です。実行可能な種目は7/8です。

公開前には、次をレビューで決めます。

- 総合スコアと「対応種目7/8」の両方を表示するか。
- 全条件一致を100%にするか、99%を維持するか。
- 下限15%を維持するか、実際の充足率に合わせるか。

この企画書は判断を提案するもので、現在の計算仕様を変更・承認するものではありません。

## 6. デザイン・利用環境

- **モバイル専従**：React Native / ExpoによるiOS・Android。Webアプリの開発は凍結。
- **主な実機**：iPhone。開発中の確認はSDK互換性を満たすExpo Goを利用。
- **デザイン**：BLACK × WHITE Monochrome Luxury。純黒、白、プラチナシルバー。
- **使いやすさ**：Safe Area、48pt以上のタッチ領域、文字拡大、明瞭な選択状態、入力エラー・空状態を重視。
- **表現**：高級感を保ちつつ、種目名・未確認情報・保存状態など、利用判断に必要な内容を読みやすくする。

## 7. 実装状況と未実装の区別

| 状況 | 内容 |
|---|---|
| 受入済み | TASK-001〜010。5タブ、ジム検索・スコア、12種目図解、家トレ、食事・体重、端末保存 |
| 実装済み・受入待ち | TASK-011。設備修正、器具・設備写真、星評価・コメント、Gyms / My Pageへの即時反映 |
| 未着手 | TASK-012。配布・ストア公開の最終準備 |
| 将来構想 | 実店舗データの継続取得、アカウント、サーバー同期、公開投稿と承認運用、実AI推定、収益化 |

### 現時点の制約

- 店舗・設備情報はプロトタイプ由来の検証用データで、実店舗の最新情報として検証済みではありません。
- データ保存は端末内。複数利用者での共有、運営への申請送信、クラウド同期は未実装です。
- 食事写真は固定 **580kcal / P52g・F16g・C55g** のモック値です。画像内容を解析せず、実AI推定として扱いません。
- 自動テストやバンドル生成と、iPhone実機での動作確認は別です。実機確認を完了済みとは扱いません。

## 8. データの信頼性を中核に置く

設備情報が誤っていれば、検索やスコアの価値も下がります。将来の公開投稿では、情報の出所と確認状態を持たせる設計を提案します。

| 情報 | 表示・運用の方針案 |
|---|---|
| 設備スペック | 最終更新日、投稿元、未確認／店舗確認済みの区別 |
| 設備写真 | 対象ジム・器具・説明・投稿日時を関連付ける |
| レビュー | 星評価とコメントを分け、誰の評価の集計かを明示する |
| 修正履歴 | 元の情報と変更後を追跡可能にする |
| 公開範囲 | 端末内の個人設定と、他の利用者に公開する情報を区別する |

現在のデータ量・更新頻度・投稿者数に実績値はありません。まず対象地域を絞った実店舗検証を提案します。

## 9. ユーザー投稿（TASK-011の実装・レビュー対象）

### 9.1 設備スペックの追加・修正

- 対象ジムを選び、ダンベル最大重量を修正する。例：40kg → 60kg。
- 不足している器具を選び、追加申請内容を登録する。
- 任意の確認メモを残し、ジムの検索・重量フィルター・適合計算へ即時反映する。
- 元データを直接書き換えず、端末内の修正履歴を重ねて表示する。
- 「この端末のみ・未検証」と表示し、運営や店舗へ申請済みと誤認させない。

### 9.2 器具写真・設備写真

- 写真ライブラリの選択とカメラ撮影に対応する。
- 対象ジム、任意の器具、説明を紐付ける。
- 再起動後も表示できるよう、選択元の一時ファイルではなくアプリ内の保存領域へコピーする。
- キャンセルや権限拒否、ファイル保存失敗では投稿を作らない。
- 今回は外部サーバーへアップロードしない。公開共有に進む場合は、写り込み・削除・通報等の運用を別途設計する。

### 9.3 星評価・レビュー

- 1〜5の星評価と、トレーニング環境に関するコメントを入力する。
- GymsとMy Pageで同じ投稿を参照する。
- 現段階の平均評価は「この端末の投稿」の集計として表示する。

### 9.4 保存・即時反映

- 既存の運動・食事・体重ログを保持して保存形式を拡張する。
- スペック、レビュー、写真の関連情報を再起動後に復元する。
- 保存中／保存失敗と再試行を利用者に示す。

## 10. 公開前に検証すること

| 観点 | 確かめる内容 |
|---|---|
| 需要 | 設備条件によってジムを探す場面が実際にあるか |
| 検索精度 | 検索結果と来店時の設備が一致するか |
| 理解しやすさ | スコアと対応種目数の違いを説明なしで理解できるか |
| 継続利用 | 初回検索後に、記録や家トレの利用へつながるか |
| 投稿品質 | 重量・器具追加が正しく登録でき、修正理由を追えるか |
| 実機品質 | 写真・キーボード・文字拡大・再起動後の保存が正常に動くか |

数値目標、対象地域、テスター数は未決定です。先に計測方法と検証範囲を決め、実績のない数字を成果として記載しません。

## 11. 収益化の仮説（未実装・未決定）

利用価値とデータ精度を確認した後、詳細な設備条件、記録分析などの付加価値を検討します。店舗との連携や紹介施策を行う場合も、検索順位と広告・紹介の関係を利用者が判断できるようにします。

現段階では価格設定や有料プランの導入を優先せず、「探した条件どおりのジムが見つかった」という体験を先に検証します。
